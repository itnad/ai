# newai 실현 가능성 검토

작성일: 2026-11-27 · 상태: 검토 완료(구현 전)

## 1. 결론

| 질문 | 판정 | 요약 |
|---|---|---|
| 로컬 터미널 프로그램으로 가능한가 | **가능** | Claude Agent SDK가 질문·계획 승인·권한 확인을 모두 콜백으로 넘겨 주므로, 하네스가 사람 대신 답할 수 있다. 실제 호출로 확인했다. |
| 웹페이지로 구현·제공이 가능한가 | **이 PC 안의 웹페이지(127.0.0.1)는 가능, 권장** | 서버가 핵심이고 터미널 화면과 웹 화면은 같은 서버를 보는 두 개의 창이다. |
| 다른 사람에게 인터넷 서비스로 제공 | **기술적으로 가능하나 이번 범위에서 제외 권장** | 사용자별 격리 실행 환경, 사용자별 API 키, 인증, 비용 관리가 필요하다. 별도 프로젝트 규모다. |
| 외출 중 내 PC의 newai에 답하기 | **가능** | 서버를 인터넷에 열지 않고 Telegram/Slack 버튼으로 답한다(서버가 바깥으로만 접속). |

## 2. 실제로 확인한 것 (이 컨테이너, Linux, Node 22, Claude Code 2.1.332, Agent SDK 0.3.332)

| # | 가정 | 방법 | 결과 |
|---|---|---|---|
| 1 | SDK `canUseTool`로 AskUserQuestion을 가로채고 하네스가 답을 넣을 수 있다 | 실제 Claude 호출(Haiku 5.5), 답에 `answers` 채워 `allow` 반환 | **통과**. 모델이 하네스가 고른 "파랑"을 받아 그대로 답함 |
| 2 | 답을 오래 붙잡아 둬도 세션이 끊기지 않는다(대기 타이머 전제) | 콜백에서 70초 보류 후 답 | **통과**. 70초 보류는 76초, 21분 보류는 1265초 후 정상 완료 |
| 3 | 같은 세션 이어가기(`resume`) | 1번 세션 ID로 이어서 질문 | **통과**. 앞 대화의 색을 기억함 |
| 4 | 이어진 세션의 `total_cost_usd`는 누적 합계다 | 1번 0.00730, 이어진 3번 0.00817 | **누적으로 확인**. SDK 타입 주석도 "이어진 세션은 저장된 합계에서 계속"이라고 명시. 기록은 직전 값과의 차이로 해야 한다 |
| 5 | 판단 모델을 프로젝트 설정·CLAUDE.md 없이 띄울 수 있다 | `settingSources: []`, 빈 폴더 `cwd` | **가능**. 단, SDK 기본값이 "모든 설정 읽기"로 바뀌어 있어 반드시 `[]`를 명시해야 한다 |
| 6 | 평소 Claude Code(대화형)에서도 훅으로 질문에 답할 수 있다(브리지) | 가짜 TTY로 대화형 `claude` 실행, PreToolUse 훅이 `updatedInput.answers` 반환 | **통과**. 화면에 "사과와 배 중 무엇을 원하시나요? → 배" 표시 |
| 7 | 비대화형 `claude -p`에도 브리지가 필요한가 | 같은 요청을 `-p`로 실행 | `-p`에서는 AskUserQuestion 도구가 아예 없다. 브리지는 대화형 세션 전용으로 설계 |
| 8 | git push를 환경 변수만으로 원천 차단 | `GIT_CONFIG_COUNT` + `url.newai-blocked://.pushInsteadOf` | **통과**. 로컬 경로·https·스크립트 안의 push 모두 실패, fetch는 정상, 변수를 빼면 push 성공(릴리스 단계용) |
| 9 | 가려진 요소 클릭을 오류로 잡기 | Playwright 1.63 | **통과**. "덮개 div가 포인터를 가로챔" 오류, 콘솔 오류 수집, 스크린샷 저장 |

시험 코드는 세션 임시 폴더에 있었고 저장소에는 넣지 않았다. 구현 단계에서 같은 내용을 정식 테스트로 옮긴다.

## 3. 확인하지 못한 것과 위험

| 항목 | 상태 | 대응 |
|---|---|---|
| 20분 보류 | 이 환경(Linux, SDK 0.3.332)에서는 21분 보류가 통과했다. Windows와 다른 버전은 미확인 | 기본은 보류 방식. 서버 재시작 대비로 `interrupt` 후 `resume` 방식도 2단계에서 구현 |
| 사용량 한도 메시지 형식 | 한도에 일부러 걸 수 없어 미확인. SDK에는 `rate_limit` 오류 유형과 `get_usage`의 `resets_at`(재설정 시각)이 있다 | 오류 유형 + 문구 + `get_usage` 세 가지로 판별. 가짜 러너로 반복 로직 시험 |
| Windows 전용 항목 | 이 컨테이너는 Linux라 Windows 터미널 화살표 키, 작업 스케줄러, EBUSY를 확인할 수 없다 | 처음부터 `harness keytest`·대체 키·원자적 파일 쓰기로 설계. **사용자 Windows PC에서 확인 필요** |
| 브리지의 권한 확인(PermissionRequest 훅) | 타입 정의로 형식만 확인, 실제 호출 미확인 | 2단계 브리지 시험에 포함 |
| 명령 차단의 완전성 | Bash 명령 문자열 검사는 `eval`, base64 등으로 우회될 수 있다 | 여러 겹(훅 + git 환경 변수 + 경로 감시 + 자격 증명 분리)으로 막고, 한계를 보안 정책 문서에 명시 |

## 4. 인증과 약관 주의

- 개인 PC에서 본인이 설치·로그인한 Claude Code를 newai가 구동하는 것은 개인 사용이다.
- Agent SDK 문서는 제3자 제품이 사전 승인 없이 claude.ai 로그인(구독 한도)을 제공하는 것을 허용하지 않는다고 안내한다. 다른 사람에게 서비스로 제공하려면 각 사용자의 API 키를 써야 한다.
- 약관은 바뀔 수 있으므로 배포 전에 최신 문서를 다시 확인한다.

## 5. 웹 제공 방식 비교

| 방식 | 가능 | 노력 | 권장 |
|---|---|---|---|
| A. 이 PC 안 웹 화면 `http://127.0.0.1:포트` + 터미널 화면 | 가능 | 기본 범위 | **1순위** |
| B. A + Telegram/Slack 원격 답변 | 가능 | 소 | **함께 구현(필수 기능 6)** |
| C. A + 개인 원격 접속(Tailscale 등 사설망, 토큰 인증) | 가능 | 소 | 선택 기능. 공개 인터넷에 직접 열지 않는다 |
| D. 다중 사용자 인터넷 서비스 | 가능 | 대(격리 컨테이너, 계정, 과금, API 키 보관) | 이번 범위 제외. 필요하면 Managed Agents 같은 호스팅형 실행을 별도 검토 |
